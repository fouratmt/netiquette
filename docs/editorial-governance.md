# Editorial governance

## Ownership

The project owner is the final approver for the MVP catalog, impact ratings,
translations, and release. Contributors propose content changes through pull
requests so wording, links, and route stability can be reviewed together.
Behavior wording is edited in `content/etiquettes/` using the instructions in
`content/README.md`; contributors do not need to edit application code.

## Reporting a problem

Visitors and reviewers should report incorrect etiquette, outdated platform
claims, translation problems, or accessibility barriers through this
repository's GitHub Issues. A report should include the entry URL, language,
the questionable wording, and a suggested correction or supporting source when
available.

## Review rules

- Preserve published slugs unless a redirect plan is included.
- Keep the voice kind, neutral, non-accusatory, and practical.
- Require all three translations before publishing a new entry.
- Review impact levels independently from the person receiving the link.
- Prefer durable behavioral advice over claims about a platform's temporary UI.
- Support named-platform visibility or privacy claims with current first-party
  documentation during review.
- Ask fluent French and Tunisian Arabic readers to approve material copy
  changes before formal release.

## Review cadence

Named-platform claims should be reviewed every three months and after a major
Instagram, Facebook, Messenger, or WhatsApp privacy/audience change. General
etiquette entries should receive a yearly tone and relevance review.

Analytics remain out of scope for the MVP. Any future measurement proposal must
first document its purpose, retention, consent behavior, and data boundaries.
